Help

This dashboard is a window on the brain — the Obsidian vault under docs-arc42-brain/. It reads the vault on every request and reloads by itself when a file changed; it never edits a page. Curating happens in Obsidian (every detail page has an Open in Obsidian link) or in an editor. The dashboard has exactly two write actions, both on the Actions page, and both described below.

How content flows

Three layers, each owned by someone different:

  1. raw/ — verbatim copies of the site's files, immutable, human-owned. make brain-raw SECTION=N puts them there; an SRC-NNN page records what was copied, with a checksum per file.
  2. wiki/ — the typed pages: sections, tips, examples, terms, keywords, systems, issues. make brain-import turns a raw batch into drafts; the ingest workflow then reads them, maps every legacy site tag to a term or a keyword, fills related:, raises an issue for every contradiction, and lifts each page to review.
  3. The site — _pages/section-*.md, _posts/*/*.md, _examples/*.md and the images beside them. Nobody writes these by hand once a section is cut over: generate does, from the published pages only.

Page vs. Ingest

The Sections table carries two states side by side, and they answer different questions. This is the distinction that column pair exists for: a section page can sit at draft for months while all 24 of its tips are already ingested.

Page — the status of one page

Every page of every type carries a status: in its front matter, on one ladder. The Page column shows it for the section page itself, and nothing else.

StatusMeans
draftBeing worked on. Still carries legacy-tags, or has no related: yet. Not emitted.
reviewContent complete: vocabulary mapped, links filled, lint clean. Waiting for a human to look at it. Not emitted.
publishedCut over. generate writes this page's site file, and the site serves the generated version.
retiredWithdrawn. Not emitted; its URL must be listed in _system/retired-permalinks.txt with a reason.

Ingest — how far a section's content has come

Derived, not stored: computed from the section's brain pages and the site's own files. A section is ingested when no tip or example of it lives only on the site any more.

StateMeans
not ingested The brain has no tip and no example for this section. The site's originals are all there is.
partial Some of the section's site files have a brain page, some do not — a half-finished ingest.
ingested Every tip and example the site carries under this section exists as a brain page. The site is still serving its own originals until cut-over.
cut over The section page is published: braingen owns this section's files on the site.

Ingested says nothing about the status those pages carry — they may all still be draft. For the full picture of what a section still needs, use Cut-over readiness.

Lint

Lint validates the vault against the schema in CLAUDE.md: front-matter fields per type, allowed status values, every [[wikilink]] resolving, #heading targets existing and being unique, images existing, no Liquid in a wiki body, no duplicate permalink, no unknown directive, no legacy-tags left on a page past draft, and related: links being reciprocated.

  • Errors block publishing. generate lints first and refuses to write anything while one error stands.
  • Warnings never block. They are judgement calls, and some are deliberate: an ISS-NNN page lists every page it affects in related:, and content pages must not link back to an issue, so every issue produces reciprocity warnings by design. A reciprocity warning between two content pages, though, is a missing backlink — fix it.

Findings are grouped by rule on the Lint page, and each names the page it came from.

Publish — the “Lint + generate” button

On Actions. It runs make brain-lint and then, only if that is clean, make generate, and appends one line to _system/log.md. What generate does:

  • Emits every published brain page — and only those — into _pages/section-*.md, _posts/*/*.md, _examples/*.md, copying referenced images to assets/images/. Wikilinks become site links, terms and keywords become the page's tags:.
  • Marks each file it writes with a braingen line as the last front-matter entry (“do not edit”). make brain-check-generated fails if such a file was hand-edited or has gone stale, and generate refuses to overwrite a hand-written file that is not marked.
  • Records every new URL in _system/published-permalinks.txt, which is append-only, and refuses to run if a URL already recorded there would disappear. Jekyll has no redirect plugin here, so a dropped URL is a hard 404. Retiring a URL on purpose means listing it in _system/retired-permalinks.txt with a reason.
  • Reports N written, N deleted, N unchanged, and the page then shows git status --short and git diff --stat so you can see exactly what moved.

Publishing is not deploying. generate only writes files into the working tree. Nothing reaches docs.arc42.org until those changes are committed and the commit lands on main, where GitHub Pages builds the site. Review the diff, then commit.

Preview (parity)

make generate-check: renders the brain into build/parity/ and diffs it, section by section, against the file the site currently has. It writes nothing into the site, so it is always safe to run — including for sections that are still draft, because parity plans draft, review and published pages alike.

  • PASS — the generated file matches the site's original, so cutting over would change nothing a reader sees.
  • FAIL — there is a difference. The report says which: body text, front matter, or tags. Tag differences are reported after alias normalisation, so a legacy tag that a term claims via aliases or legacy-tags counts as matched.

The last result is cached and shown in the Parity column on Sections, Actions and Cut-over. A dash means no preview has run since the dashboard started.

Cut-over

Cutting a section over means setting its pages to published and running generate: from then on the brain owns those site files and hand-edits there are lost. Cut-over readiness checks the preconditions per section:

ColumnMeans
Cut overThe section page is already published.
IngestedNo site file of this section is without a brain page.
Lint cleanNo lint error on this section's pages.
ParityThe last preview's verdict for this section.
RelatedEvery tip and example of the section has at least one related: link — the ingest step that is easiest to forget.
ReadyAll of the above, and not yet cut over. The banner names the next one.

The other pages

Home
One tile per area, each linking to its page. Use it as the daily starting point: counts, lint totals, review queue, readiness, recent log entries and commits.
Tips, Examples, FAQ, Terms, Keywords, Systems
One list per content type, filterable by status, section and system. Terms and keywords also show how many pages reference them — a term with usage 0 is either premature or forgotten.
Tags
The two vocabularies together: terms (arc42 concepts, with a definition and a home) against keywords (navigation facets), plus every legacy site tag and the term that now claims it. Terms without a definition sentence or a home are called out.
Issues
Open ISS-NNN pages by severity and kind. Contradictions and doubts found while ingesting become issues, never silent edits.
Review
Every page at review, oldest change first, with the ingest workflow's own checklist beside it.
Gaps
Structural holes: tips with no example, examples with no tip, subsections nothing links to, sections nothing references.
Suggestions
Candidate related: pairs the vault does not have yet, scored, with the reason for each. A proposal to judge, not a to-do list.
Links
External URL health, checked on request and cached: failures and redirects first, with the pages naming each URL.
Graph
The link graph, or the term graph (?kind=terms).
Log
The newest entries of _system/log.md — one per operation, append-only — and recent git commits.
Search
Titles, bodies and front matter across the vault.

Who can do what

Every open tab sends a heartbeat and gets a nickname; Who's here lists them. The tab that connected first and is still around is the facilitator, and only the facilitator can start generate or preview — everyone else watches the run live. Nothing about presence is stored: a server restart clears it, and the next tab to ping becomes facilitator.

Reload in the header drops the cached vault. You rarely need it — the cache already reloads when a file under wiki/, raw/sources/ or the generated site folders changes — but it is the right button after a git checkout.

Where the rules live

The dashboard reports; these files decide:

docs-arc42-brain/CLAUDE.md
The schema: types, folders, required fields, the status ladder, the two vocabularies, linking rules.
_system/workflows/
ingest.md (the nine steps), cutover.md, audit.md, relations.md, bootstrap.md.
_system/adr/
Why the brain is built this way.
_system/log.md
Append-only record of every operation.

The same work from a terminal:

CommandDoes

make generate-check SECTION=NParity, without writing to the site.
make generateWrite the site files of all published pages.

make brain-testbraingen's unit tests.
