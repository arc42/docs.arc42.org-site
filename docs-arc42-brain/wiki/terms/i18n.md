**Definition.** Building a system so that it can work in more than one language and locale,
decided once rather than per feature.

**In arc42.** One of the crosscutting concepts section 8 exists for: it touches nearly every
building block, so it cannot be documented inside any of them. Section 12 meets it from the other
side — [[tip-12-4]] asks for a column per language in the [[glossary]] table, because a
distributed team with requirements in one language and developers in another needs a *normative*
reference for the important terms, not an ad-hoc translation each time.

**Distinguish from.** [[glossary]] — the glossary is where the agreed terms and their translations
are written down; internationalization is the property of the system that makes several languages
possible in the first place.

**Note on the tag.** The site's tag is `i18n` and the slug follows it, so the emitted tag keeps
that spelling; the display form is the full word, with `Internationalization` and the British
spelling as aliases.
